## 0. 一句话版本

以前是「一个数据库装下所有比赛，改一处代码全系统心跳」；  
现在是「每场比赛一个库、规则写成插件、交付打成包、部署一条命令」。

重构不是把代码搬家，是把未来搬了进来。

---

## 1. 地基篇：从大通铺到一人一间

### 1.1 每场比赛，一个数据库

- 全局库 `default` 管用户、比赛、队伍、包、日志；
- 每场比赛独立 `comp_<id>`，公司、合同、产业字段、财年、基础数据全在里面；
- `ctx.set_competition_context(cid, alias)` 负责切换，`register_competition_db()` 负责路由，`provisioning.ensure_competition_db()` 负责「没有就建」。

一句话：**比赛之间不再互相串味，删库也只删自己那一间。**

### 1.2 导入失败？整间房回滚

比赛包导入是「建库 → 迁移 → 插件 → 数据」的长流程。现在任一阶段报错：

- 本次新建的比赛库直接删除；
- 插件注册回滚；
- 导入报告落库，错误带文件名、行号、原因。

不会出现「导入到一半，留下一个半成品比赛」的尴尬现场。

### 1.3 PgBouncer：连接池上岗

- 默认启用 PgBouncer，事务池模式，应用连 `127.0.0.1:6432`；
- Django 自动关闭服务端游标（`DISABLE_SERVER_SIDE_CURSORS`），否则事务池下会翻车；
- 部署脚本会先验直连，再验 6432；失败自动回退直连并改 `.env`，不让服务起不来；
- 改完 `userlist.txt` 必须 `restart`，`enable --now` 不会重载——这是踩过的坑，已写进脚本。

## 2. 比赛包篇：一个 zip 的成年礼

### 2.1 包格式升级到 v1.2

一个比赛包现在可以带：

| 内容 | 作用 |
| --- | --- |
| `manifest.yaml` | 包版本、插件清单、文件哈希、仪表盘/区域字段入口 |
| `plugins/contract_*.py` | 合同类型：参与方、输入项、检查、落账 |
| `plugins/industry_*.py` | 产业类型：字段、公式、默认值、财年定时器 |
| `sheets/industries.xlsx` | 产业信息与字段对账（插件才是权威） |
| `sheets/contracts.xlsx` | 合同实例（公司必须已存在） |
| `sheets/<基础数据>.xlsx` | 燃料/仓库/载具/地图/原料/产品/零件/基建/科技/生产线 |
| `dashboard.json` | 仪表盘布局：组件绑定产业字段值 |
| `region-fields.json` | 比赛级区域字段定义 + 修改条件 |

### 2.2 表格的定位，终于说清楚了

- **表格用来导入「数据管理」里的基础数据**：按 `code` upsert，未识别列进 `meta`；
- **不再导入公司数据**：合同里的 `companyName` 必须已在系统中存在，否则该行报错；
- 公司从组队/分配产生，不从 zip 里「凭空长出来」；
- 示例包和脚手架里的 `contracts.xlsx` 只留表头，避免新环境导入即失败。

### 2.3 导入流水线

```
解压 → manifest / SHA-256 校验 → 插件 AST 扫描
     → 建库 + migrate → 产业字段迁移
     → 基础数据（数据管理）导入
     → 合同实例导入
     → 导入报告
```

每一站都有「拒绝通行」的理由：哈希不对、插件用了 `os.system`、表格少列、引用悬空、公司不存在……报告里写清楚，不靠猜。

### 2.4 仪表盘：不再是拖拽控件，而是绑定字段

- `dashboard.json` 里写 `number / gauge / table / text` 组件；
- 每个组件通过 `bind.table + bind.fieldKey + aggregate` 绑定产业字段；
- 支持 `industries.<产业key>` 分产业页签；
- 用户只能看到自己可操作公司的聚合值。

### 2.5 区域字段：比赛级定义，区域级存值

- `region-fields.json` 定义一套字段，所有区域共用；
- 值按区域存；
- `condition` 控制合同修改该字段的附加条件：公司字段（`COMPANY`）或区域字段（`REGION`）。

## 3. 插件 SDK：从「有补全」到「真能帮忙」

最初的 SDK 只有类型提示，写起来仍要手拼 dict；现在：

### 3.1 构造函数

```python
from bcm_plugin_sdk import (
    InputSchema, PartyRoles,
    number_field, list_field, list_sub_field, party_role,
    industry_field, industry_bool_field,
    region_field, region_condition, region_fields_document,
)
```

- 合同输入项：`number_field / text_field / bool_field / ref_field / list_field`
- 产业字段：`industry_field / industry_number_field / industry_text_field / industry_bool_field`
- 区域字段：`region_field / region_condition / region_fields_document`

所有可选参数都支持位置传参，也支持关键字——不再因为「少写一个 `*`」被 Pylance 教育。

### 3.2 静态校验 CLI

```powershell
python -m bcm_plugin_sdk check plugins/contract_x.py
python -m bcm_plugin_sdk check --all plugins/
```

检查语法、危险 import/调用、必需常量与函数、签名、角色/输入项重复、字段类型、清单表名、产业字段归属。

### 3.3 编辑器体验

- `.vscode/settings.json` + `pyrightconfig.json`：`extraPaths` 指向 `tools/plugin-sdk`；
- 包工程 `init` 会自动生成这两个文件，单独打开包目录也能识别 SDK；
- `ctx` 方法补齐了文档（`party`、`company_field`、`basedata`、`field` 等）；
- 产业字段专用构造器，避免把合同 `bool_field` 塞进 `FIELDS` 的类型事故。

### 3.4 运行时装得上

部署脚本会在 `uv sync` 后安装 `tools/plugin-sdk`，插件运行时可以放心 import 构造函数（只返回 dict/list）。

## 4. 比赛包工程工具：init / check / build

```powershell
python tools/package-tools/package_tools.py init my_package
python tools/package-tools/package_tools.py check my_package
python tools/package-tools/package_tools.py build my_package --out dist/my_package.zip
```

- `init`：脚手架，含 manifest、合同/产业插件、产业/合同表、dashboard、region-fields、编辑器配置；
- `check`：manifest 结构、sha256、插件 AST/常量/类型、表格表头与交叉引用、仪表盘、区域字段、zip 路径穿越；
- `build`：重算 sha256 → 校验 → 打包；`check` 不通过就不出包；
- 直接传目录等价于 `check`，不写子命令也不会再报 `invalid choice`。

## 5. 权限篇：谁能按哪个按钮

| 场景 | 规则 |
| --- | --- |
| 创建合同 | 仅系统超管 / 主席团；参赛选手隐藏入口，API 同步拒绝 |
| 合同操作 | 参赛选手只读：提交/确认/拒绝/终止/修改/审核全部关闭 |
| 主席团建合同 | 参与方下拉可选全部公司（`?all=1`），不再「无数据」 |
| 组队管理 | 仅系统超管；主席团侧栏隐藏，路由守卫兜底 |
| 财年管理 | 仅系统超管；主席团不可见 |
| 侧栏文案 | 非超管「数据管理」显示为「数据」 |

细节也补了：

- 新建合同校验从 toast 改成字段下方内联提示；
- 合同工作台去掉类型下方的参与方/字段摘要；
- 消息中心按钮恢复右对齐，`PageHeader` 操作区补回 8px 间距。

## 7. 部署篇：一条命令的自我修养

`deploy/debian/deploy.py` 重写为四个模式：

```bash
./install.sh                 # 安装
./install.sh upgrade         # 升级
./install.sh doctor          # 体检
./install.sh status          # 看状态
```

能力清单：

- **默认系统 nginx**；识别 1Panel / OpenResty，占用时给方案（停 OpenResty 或改 8080）；
- **纯 IP 部署**自动探测本机 IP，跳过证书；
- **域名部署自动申请 Let's Encrypt**，失败回退 HTTP，装续期 timer；
- **PgBouncer 自动安装**、写配置、重启、验连接、失败回退；
- uv Python 固定到 `/opt/uv-python`，避免 `/root` 权限导致的 203/EXEC；
- 数据库不存在时按输入的用户/库名自动创建；
- 管理员账号不存在时自动创建并校验，支持改密；
- rsync 排除规则锚定根目录，避免漏拷 `apps/global_/logs`；
- 支持 `--site-dir` 同步前端 dist 到 1Panel 站点目录；
- 幂等：重复执行不会把配置越改越乱。

## 9. 升级须知（不看会踩的坑）

1. **PgBouncer**：确认 `.env` 的 `DB_PORT=6432`，并保留 `DATABASES_DISABLE_SERVER_SIDE_CURSORS=true`；改 `userlist.txt` 后必须重启 PgBouncer。
2. **比赛包**：改完插件/表格必须重新 `build`，否则 sha256 校验失败。
3. **公司**：合同导入前先在系统中创建/分配公司，不再自动建档。
4. **基础数据**：包里的 `fuels.xlsx` 等现在会真正导入「数据管理」，旧包重导会更新这些表。
5. **manifest**：`hostSchool` / `location` 已不再读取，写不写都不影响导入。
6. **SDK**：要求 Python ≥ 3.11；部署脚本会自动安装，手工环境用 `uv pip install -e tools/plugin-sdk`。
7. **nginx**：默认接管系统 nginx；1Panel 用户请用 `--nginx-mode manual` 或先停 OpenResty。
