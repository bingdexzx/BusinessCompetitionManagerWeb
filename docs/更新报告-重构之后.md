# BusinessCompetitionManager 重构更新报告

> 版本：v1.2  
> 日期：2026-11-25  
> 范围：多库重构落地后，至本次比赛包、权限、部署与工具链更新  
> 状态：已完成开发与回归验证

---

## 1. 摘要

本轮更新以「多数据库隔离」重构为基础，完成了比赛包格式与导入流程、插件开发工具链、权限模型、前端交互、品牌资源及 Debian 部署脚本的系统性调整。

核心变化可概括为：

- 每场比赛使用独立数据库，比赛间数据隔离，导入失败可整体回滚；
- 比赛包升级至 v1.2，支持产业/合同插件、基础数据表、仪表盘布局与区域字段定义；
- 基础数据表改为导入系统「数据管理」，公司不再由比赛包自动创建；
- 新增比赛包工程工具（init / check / build）与插件 SDK（类型提示、构造函数、静态校验）；
- 合同权限收紧：仅系统超管/主席团可创建，参赛选手只读；
- 部署脚本重写为 install / upgrade / doctor / status 四种模式，默认系统 nginx、PgBouncer，并支持自动申请证书。

---

## 2. 背景与目标

重构前，系统采用单库承载全部比赛数据，存在以下问题：

- 比赛间数据边界不清晰，删除或迁移比赛影响面大；
- 比赛包只覆盖部分资源，导入失败缺少完整回滚；
- 插件编写依赖手写字典，缺少类型约束和校验手段；
- 部署脚本对 1Panel/OpenResty、数据库连接、证书等环境差异处理不足；
- 合同与比赛管理权限粒度较粗。

本轮目标：

1. 建立可隔离、可回滚的多库数据模型；
2. 把比赛交付标准化为可校验、可打包的比赛包；
3. 提升插件开发与部署运维的可控性；
4. 收紧关键业务操作权限，减少误操作。

## 3. 架构与数据层

### 3.1 多数据库隔离

- 全局库 `default`：用户、比赛、队伍、比赛包、系统日志等全局数据；
- 比赛库 `comp_<id>`：公司、合同、产业字段、财年、基础数据等比赛内数据；
- 通过 `ctx.set_competition_context()` 切换比赛上下文，`register_competition_db()` 完成路由；
- `provisioning.ensure_competition_db()` 负责比赛库不存在时自动创建并迁移。

### 3.2 导入回滚

比赛包导入按阶段执行：

```
解压 → manifest / SHA-256 校验 → 插件 AST 扫描
     → 建库 + migrate → 产业字段迁移
     → 基础数据导入 → 合同实例导入
     → 导入报告
```

任一阶段失败时：

- 本次新建的比赛库直接删除；
- 插件注册回滚；
- 失败原因写入导入报告，包含文件、行号与具体问题。

### 3.3 PgBouncer 连接池

- 默认启用 PgBouncer 事务池，应用连接 `127.0.0.1:6432`；
- 启用 `DISABLE_SERVER_SIDE_CURSORS`，适配事务池模式；
- 部署脚本先验证直连，再验证 6432；
- 连接失败时自动回退直连并同步 `.env`；
- 修改 `userlist.txt` 后强制重启 PgBouncer，确保认证配置生效。

## 4. 比赛包与插件体系

### 4.1 包格式 v1.2

| 内容 | 说明 |
| --- | --- |
| `manifest.yaml` | 包版本、插件清单、文件哈希、仪表盘/区域字段入口 |
| `plugins/contract_*.py` | 合同插件：参与方、输入项、检查、落账 |
| `plugins/industry_*.py` | 产业插件：字段、公式、默认值、财年定时器 |
| `sheets/industries.xlsx` | 产业信息与字段对账（以插件 `FIELDS` 为准） |
| `sheets/contracts.xlsx` | 合同实例（可选） |
| `sheets/<基础数据>.xlsx` | 燃料、仓库、载具、地图、原料、产品、零件、基建、科技、生产线 |
| `dashboard.json` | 仪表盘布局，组件绑定产业字段 |
| `region-fields.json` | 比赛级区域字段定义与修改条件 |

### 4.2 基础数据导入

- 支持 10 类基础数据表，文件位于 `sheets/<表键>.xlsx`，也支持根目录或 CSV；
- 按 `code` 执行 `update_or_create`，可重复导入；
- 未识别列写入 `meta`，避免数据丢失；
- `fuelCode`、`regionCode` 等引用必须在同包对应表中存在；
- 单表行数上限 50,000，超限或格式错误阻断导入。

### 4.3 公司数据策略

- 比赛包不再导入公司数据；
- 合同中的 `companyName` 必须已在系统中存在，否则该行报错；
- 公司由组队、分配等业务流程产生；
- 示例包与脚手架中的 `contracts.xlsx` 仅保留表头，避免新环境导入失败。

### 4.4 仪表盘与区域字段

- `dashboard.json` 支持 `number / gauge / table / text` 组件；
- 组件通过 `bind.table`、`bind.fieldKey`、`aggregate` 绑定产业字段；
- 支持按产业 key 划分页签；
- `region-fields.json` 定义比赛级区域字段，值按区域存储；
- 区域字段可配置 `condition`，限制合同修改该字段的条件。

## 5. 插件开发工具链

### 5.1 插件 SDK

- `ContractContext` / `IndustryContext` / `Effect` 提供完整类型提示与参数说明；
- 新增字段构造函数：
  - 合同输入项：`number_field`、`text_field`、`bool_field`、`ref_field`、`list_field`、`list_sub_field`、`party_role`；
  - 产业字段：`industry_field`、`industry_number_field`、`industry_text_field`、`industry_bool_field`；
  - 区域字段：`region_field`、`region_condition`、`region_fields_document`；
- `TableName`、`FieldType` 等字面量约束表名与输入类型；
- 所有构造函数的可选参数支持位置传参与关键字传参。

### 5.2 静态校验

```bash
python -m bcm_plugin_sdk check plugins/contract_x.py
python -m bcm_plugin_sdk check --all plugins/
```

校验范围：

- 语法与危险 import/调用；
- 合同/产业插件必需常量与函数；
- `check(ctx)` / `apply(ctx)` 签名；
- 参与方角色、输入项 key 是否重复；
- 输入项类型、清单表名、子字段；
- 产业字段 `table` 归属。

### 5.3 编辑器与运行时

- 仓库提供 `.vscode/settings.json` 与 `pyrightconfig.json`，`extraPaths` 指向 `tools/plugin-sdk`；
- 包工程 `init` 自动生成同等配置，单独打开包目录也可解析 SDK；
- 部署脚本在 `uv sync` 后安装 `tools/plugin-sdk`，插件运行时可使用构造函数；
- `Effect` 仍由引擎注入，插件中通过 `TYPE_CHECKING` 引用。

### 5.4 比赛包工程工具

```bash
python tools/package-tools/package_tools.py init my_package
python tools/package-tools/package_tools.py check my_package
python tools/package-tools/package_tools.py build my_package --out dist/my_package.zip
```

- `init`：生成 manifest、插件模板、产业/合同表、仪表盘、区域字段与编辑器配置；
- `check`：校验 manifest、sha256、插件结构、表格表头与交叉引用、仪表盘、区域字段、zip 路径安全；
- `build`：重算 sha256、执行校验、打包 zip；校验失败不产出包；
- 直接传目录等价于 `check`，减少命令记忆成本。

| 场景 | 规则 |

## 8. 部署与运维

`deploy/debian/deploy.py` 重写为四种模式：

```bash
./install.sh                 # 安装
./install.sh upgrade         # 升级
./install.sh doctor          # 体检
./install.sh status          # 状态
```

主要能力：

- 默认使用系统 nginx；识别 1Panel / OpenResty，并在端口占用时给出处理方案；
- 纯 IP 部署自动探测本机 IP，跳过证书；
- 域名部署默认自动申请 Let's Encrypt 证书，失败回退 HTTP，并安装续期 timer；
- 自动安装并配置 PgBouncer，失败回退直连；
- uv Python 固定安装目录，避免 `/root` 权限导致服务无法启动；
- 数据库不存在时按输入参数自动创建；
- 管理员账号缺失时自动创建并校验，支持修改密码；
- rsync 排除规则锚定根目录，避免遗漏 `apps/global_/logs`；
- 支持 `--site-dir` 将前端 dist 同步至 1Panel 站点目录；
- 全流程幂等，可重复执行升级。

## 10. 兼容性与升级注意事项

1. **PgBouncer**：确认 `.env` 使用 `DB_PORT=6432`，并保留 `DATABASES_DISABLE_SERVER_SIDE_CURSORS=true`；修改 `userlist.txt` 后需重启 PgBouncer。
2. **比赛包哈希**：修改插件或表格后必须重新执行 `build`，否则导入时 sha256 校验失败。
3. **公司数据**：合同导入前需先在系统中创建或分配公司，比赛包不再自动建档。
4. **基础数据**：包内 `fuels.xlsx` 等基础数据表现在会导入「数据管理」，旧包重导会更新对应表。
5. **manifest 字段**：`hostSchool`、`location` 不再读取，写或不写均不影响导入。
6. **SDK 环境**：要求 Python ≥ 3.11；部署脚本自动安装，手工环境使用 `uv pip install -e tools/plugin-sdk`。
7. **nginx 模式**：默认接管系统 nginx；1Panel 环境请使用 `--nginx-mode manual` 或先停 OpenResty。
