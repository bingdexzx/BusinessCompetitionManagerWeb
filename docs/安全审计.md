## 2. 检查通过（无需修改）

| 项 | 现状 |
| --- | --- |
| DEBUG | 默认 `false`，仅环境变量开启 |
| ALLOWED_HOSTS | 默认仅 localhost/127.0.0.1；显式环境变量才放开 |
| Cookie | HttpOnly + `SameSite=Lax` + 非 DEBUG 默认 Secure |
| CORS | 仅 `localhost:5173` / `127.0.0.1:5173`，非通配 |

| 登录防爆破 | `accounts.throttle` 失败计数 + 锁定窗口；`TRUST_X_FORWARDED_FOR` 默认关闭，避免伪造 IP 绕过 |

| 日志接口 | 仅系统超级管理员可读 |
| SQL | 全项目无用户输入拼接的 SQL（仅有内部生成的表名/库名，来自受控值） |
| 公式/插件执行 | 公式用 AST 白名单求值；插件导入前 AST 扫描，禁危险调用 |

## 3. 待部署侧处理（非代码缺陷）

1. **HSTS / HTTPS 重定向**：本地 HTTP 默认关闭；生产设置
   `SECURE_SSL_REDIRECT=1`、`SECURE_HSTS_SECONDS=31536000`、`TRUST_X_FORWARDED_PROTO=1`。
2. **反向代理**：WS token 走 query string，需确认 nginx/网关**不记录 query**（或改为
   `Sec-WebSocket-Protocol` 承载 token）。
3. **密钥轮换**：`SECRET_KEY` 轮换会使所有 refresh token 失效，需通知用户重新登录。
4. **数据库连接**：生产使用独立 DB 账号（非 postgres 超级用户），只授予所需库权限。

## 4. 已知残余风险（低）

- `/api/files/view/` 对**任意登录用户**开放（靠 UUID 文件名不可猜）；如需更严格，可加「文件所属比赛成员」校验。
- JWT 存于前端 localStorage，若发生 XSS 可被读取；建议后续接入短时 access + refresh 轮换/黑名单。
- `v-html` 仍用于奖牌样式（已做白名单清洗，非通用 sanitizer）。
- 插件在进程内执行（AST 扫描不是沙箱）；只应导入可信比赛包。
