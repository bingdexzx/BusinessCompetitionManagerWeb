# 《实时同步覆盖》——哪些数据能实时同步、怎么加

> 2026-10-27 审计；**2026-11-25 复核**：论坛功能已移除；合同列表改为「WS 事件整页重拉」
> （修复别处删除合同后列表不消失）；新增 `companies` 广播（公式重算后公司页刷新）；
> 目录型缓存（合同类型/公司列表/基础数据/字段定义）由广播自动失效。
> 原结论：**业务数据已全覆盖**（写入后所有在线页面按资源自动重拉）；
> 本次修掉了 6 处「资源名不匹配 / 漏订阅」导致的不刷新，并补了一个可重复运行的验证脚本。

## 1. 机制（先看懂这三点，才能判断"某个数据会不会实时"）

1. **广播是自动的**：`apps/common/middleware.py` 在**每个成功的写请求**（POST/PATCH/PUT/DELETE，状态 <400）后，
   按 **URL 路径**推导资源名并广播，不需要各视图手写 emit：
   - `/api/<资源>/...` → 全局作用域（投 `global` 分组）
   - `/api/competitions/<cid>/<资源>/...` → 比赛作用域（投 `comp_<cid>` 分组）
   - 别名：`meta`/`transition` → `competitions`；`package` → `packages`
2. **事件落库 + 推送**：`BroadcastEvent`（`seq` 单调递增）是重放源，`pg_channel_layer` 推送只是信号
   （不带业务数据）。断线重连带 `lastSeq` 由 `events_since()` 补发，不会漏。
3. **前端只按「资源名」匹配**（`useResourceRefresh([...])`，**不看作用域**），400ms 去抖合并；
   后台标签页只标脏、回前台再刷。所以：**名字对不上 = 该页永不刷新**。

### 不广播的路径（刻意跳过）
`/api/auth`、`/api/me`、`/api/messages`、`/api/logs`、`/api/files`、`/api/version`。
- 站内信走**独立通道**：`messages.services._push` 直接向 `user_<id>` 推 `notification` 帧，
  前端 `MessagesView` / `MessageToastHost` 消费（实测到达，见 §4）。
- `/api/me`（本人资料）与 `/api/files`（通用上传）无跨端同步需求。

## 2. 覆盖矩阵（资源 → 谁写 → 谁订阅）

| 资源 | 写入来源 | 订阅页面 |

| `members` | 成员指派/调整 | 比赛详情、用户管理 |

| `basedata` | 10 类基础数据 CRUD（含地图节点/边） | 13 处：数据管理枢纽+9 管理器+地图、仪表盘、区域总览、字段日志 |
| `companies` | 公司字段修改、赛区调整 | 组队、合同详情、仪表盘、结算、股票行情、字段日志、财年 |
| `contracts` | 建单/提交/确认/申请修改/审核/补录 | 合同工作台、合同详情、仪表盘、字段日志、财年、审计（本次新增） |

| `logs` | 字段日志导出 | 字段日志、审计日志 |

| `users` | 账号创建/改/删/重置密码 | 用户管理、比赛详情、组队、个人档案（本次新增） |
| `schools` | 学校 CRUD | 学校管理、用户管理、比赛列表 |
| `system` | 限流配置/重置 | 设置 |
| `plugins` | 无写接口（插件随比赛包导入注册） | 插件管理（同时订阅 packages） |
| `files` | 地图背景上传/变换/删除 | 地图管理 |

## 3. 本次修掉的 6 处「名义不匹配」

| 页面 | 问题 | 修法 |
|---|---|---|
| 个人档案 | **完全没有实时订阅** → 发奖/发奖牌/改资料都看不到 | 新增 `['awards','medals','users']`，同时 `auth.fetchMe()` |
| 仪表盘 | 订阅列表缺 `dashboard` → 别人改布局不生效 | 补 `dashboard` |
| 比赛详情 | 缺 `invites` / `packages` → 激活码与导入报告不刷新 | 补 `invites`、`packages` |
| 用户管理 | 订阅 `memberships`（**后端从不广播此名**） | 改为 `members` |
| 审计日志 | 只订阅 `audit-logs`/`logs`，而审计条目由合同/股票写操作产生 | 补 `contracts`、`stock` |
| 插件管理 | 插件随包导入注册（发 `packages`） | 补 `packages` |
| 站内信 | 已读状态等写入不刷新（`/api/messages` 被跳过） | 补 `['messages']`（比赛级站内信仍会广播） |
| 区域总览 | 订阅了不存在的 `map_nodes`（地图节点写入发的是 `basedata`） | 去掉死名字，保留 `basedata` |

## 5. 新增页面/接口时的检查清单

- [ ] 页面用了哪些资源？**名字必须等于 URL 路径里的那一段**（如 `/competitions/<cid>/foo-xx` → `foo-xx`）。
- [ ] 比赛级资源会自动投到 `comp_<cid>`，全局资源投 `global`；前端按**名字**匹配，不区分作用域。
- [ ] 新接口若挂在 `/api/competitions/<cid>/` 下、且需要归一到某个资源名，在 `middleware._COMPETITION_RESOURCE_ALIAS` 加别名。
- [ ] 路径若在 `_BROADCAST_SKIP` 前缀内（auth/me/messages/logs/files/version），**不会**广播——需要同步就得换通道（参考站内信的 `notification` 帧）。
- [ ] 页面卸载自动解绑（`useResourceRefresh` 已处理）；后台标签页只标脏，回前台刷新。
- [ ] 一次写操作会影响多个资源时，页面要**同时订阅多个名字**（例如导入比赛包 → `packages` 会改产业字段与合同类型）。
