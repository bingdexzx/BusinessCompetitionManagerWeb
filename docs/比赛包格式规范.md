> 状态：**v1.1**——v1.0 五项取舍经需求方确认（2026-10-10）；v1.1 导入方式变更（2026-10-12）：

## 1. 总体结构

一次导入即搭建整场比赛**产业与合同**底座的标准压缩包（`.zip`）：

```
competition_package.zip
  manifest.yaml              # 包元数据、插件清单与哈希（必须）
  plugins/
    contract_purchase.py     # 合同类型插件（一个文件一类合同）
    contract_loan.py
    industry_manufacturer.py # 产业类型插件（一个文件一个产业）
  sheets/
    industries.xlsx          # 产业信息、产业字段（对账）
    contracts.xlsx           # 合同信息（合同实例）
```

- **表格 = 数据，Python = 逻辑**：业务规则（检查/修改/公式）全部在插件里；表格只承载产业信息与合同实例。
- **基础数据不随包**：燃料/仓库/载具/地图/原料/产品/零件/基建/科技树/生产线在系统「数据管理」页维护。
- 编码：xlsx（推荐）或 csv（同名 `*.csv` 可替代 `*.xlsx`）；所有文本 UTF-8。
- 包大小上限默认 100 MB；单表格行数上限默认 50,000。

## 2. manifest.yaml

```yaml
packageVersion: "1.0"            # 包格式版本
competition:                     # 建议的比赛信息（仅随包记录，导入时不读取）
  name: "2025 商业对抗赛"
  coverImage: "https://.../cover.png"
  staffingInfo: "主席团 5 人"
# 备注：hostSchool / location 已不再从 manifest 读取，也不再参与校验；
#      办赛学校与地点请在系统「比赛信息」里维护。
plugins:
  - file: plugins/contract_purchase.py
    kind: CONTRACT               # CONTRACT | INDUSTRY
    key: purchase                # 与插件内 *_KEY 一致
    name: "采购合同"
    version: "1.0.0"             # 语义化版本；key+version+sha256 唯一
    sha256: "<文件 SHA-256>"
  - file: plugins/industry_manufacturer.py
    kind: INDUSTRY
    key: manufacturer
    name: "制造业"
    version: "1.0.0"
    sha256: "<文件 SHA-256>"
sheets:
  - file: sheets/industries.xlsx
    sha256: "<文件 SHA-256>"     # 可选；提供则校验
  - file: sheets/contracts.xlsx
    sha256: "<文件 SHA-256>"
```

校验规则：
1. `packageVersion` 主版本必须为 `1`；
2. manifest 声明的插件/表格必须真实存在，多出的文件报**警告**；
3. 声明 `sha256` 的文件逐一核对，不一致为**错误**（整包拒收）；
4. `kind` 与文件名前缀必须一致（`contract_` / `industry_`）；`key` 与插件内 `CONTRACT_KEY` / `INDUSTRY_KEY` 必须一致。
5. **所有面向用户的名称必须是中文**（界面一律显示中文名，不回退英文标识）：
   - manifest `plugins[].name`（插件中文名）：缺失时**回退为插件内置名**（`INDUSTRY_NAME` / `CONTRACT_NAME`）并记警告；
     插件内置名也为空则回退为 `key`（会以英文出现在界面上，属于不合格的包）。
   - 合同插件 `CONTRACT_NAME`、`PARTY_ROLES[].label`、`INPUT_SCHEMA[].label` 必填（空值即**拒收**）。
   - 产业插件 `INDUSTRY_NAME`、`FIELDS[].name` 必填（空值即**拒收**）——`FIELDS[].name` 就是界面上的「字段中文名」。
   - 该规则只在**导入时**校验；已导入的历史比赛不受影响。

## 3. 合同类型插件 `contract_<key>.py`

见重构方案 §8.1，必备元素：

| 元素 | 说明 |
|------|------|
| `CONTRACT_KEY` | 唯一标识（与 manifest 一致） |
| `CONTRACT_NAME` | 展示名 |
| `PARTY_ROLES` | 参与方列表 `[{role, label, optional?}]`，可扩展任意方数 |
| `INPUT_SCHEMA` | 输入定义 `[{key, label, type, min?, max?, ref?}]`，type ∈ `NUMBER/TEXT/BOOL/REF:<表格>` |
#### 3.1 可添加的输入项目录（LIST 清单）

`type` 写 `LIST:<表格>`，行结构固定为 `{item, ...fields}`（`item` 是引用条目的名称）。
`optional: True` 表示该清单可整项留空；`fields: []` 表示只登记条目（如科技树不填数量）。
下表是**当前引擎已支持的全部清单类型**，以及插件能拿到的返回值：

**清单只录「数量」，单价不进输入**（2026-11 口径）：金额在插件里按基础数据的价格现算，
所以行字段只有 `quantity` 或干脆没有；需要价格/其它数值时用
`ctx.item(<表>, <条目名>)`（返回该条目的全部数值，含价格字段）。

| `LIST:<表格>` | `itemLabel` | 行字段 | 清单引用校验 | 价格字段（`ctx.item_detail` 里取） | 旧系统口径（落账时通常改的字段） |
| --- | --- | --- | --- | --- | --- |
| `materials` | 原料 | `quantity` | 原料表存在该名称 | `ctx.price(名称, 区域)`（按地点价格） | 卖方 `yuanliaokucun` 减、买方加；买方 `yinhangzhanghu` 付给卖方 |
| `parts` | 零件 | `quantity` | 零件表存在 | 无价格字段 → 0 | 双方 `lingjiankucun` 一减一加 |
| `products` | 产品 | `quantity` | 产品表存在 | 无价格字段 → 0 | 双方 `chanpinkucun` 一减一加 |
| `map_nodes` | 地点 | **无**（只登记地点） | 地图节点存在（建议只选有名字的节点） | 无 | 旧「选址地」合同：`location` **SET** 节点名 |
| `fuels` | 燃料 | `quantity` | 燃料表存在 | `price_per_liter` | 燃料库存（产业字段暂无专用键，可写 `cangku`） |
| `tech_nodes` | 科技树 | **无**（只登记条目） | 科技节点存在 | `research_cost` | `kejishu` 追加条目（旧系统按研发一次解锁） |
| `infrastructures` | 基建 | `quantity` | 基建表存在 | `price`（激活价另有 `activation_price`） | `jijian` / `jijianshuliang`；旧「买地」还加区域面积 `quyumianji` |
| `warehouses` | 仓库 | `quantity` | 仓库表存在 | `price`（容量 `capacity`、类型 `type`） | `cangku` + 对应仓容字段（`yuanliaocangkurongliang` 等） |
| `production_lines` | 生产线 | `quantity` | 生产线表存在 | `price`（另有 `labor_count`/`max_per_year`） | `shengchanxian`，用工数按 `labor_count` 累计 |
| `vehicles` | 载具 | `quantity` | 载具表存在 | `price`（另有油耗/三类载货上限） | 载具采购/租赁，登记数量 |
| `cities` | 城市 | **无**（只登记城市） | 只认「城市点位」节点 | 无 | 按城市覆盖，等价旧「选址地」但仅城市 |
| `companies` | 公司 | **无**（只登记公司） | 公司名存在 | 无 | 一张合同对多家公司（批量拨款/集团采购） |
| `regions` | 区域 | **无**（只登记区域） | Region 名或节点区域存在 | 无 | 按区域生效的合同 |

非清单输入项：`NUMBER`（`ctx.input_number`）、`TEXT`（`ctx.input_text`）、`BOOL`（`ctx.input_bool`）。

**REF 引用项**（`REF:<表格>`）：界面上是「可搜索下拉」，值存条目名称；提交时校验存在性
（以前只校验非空）。支持 `REF:companies` / `REF:regions` / `REF:cities` / `REF:map_nodes` /
`REF:vehicles` / `REF:products` / `REF:parts` / `REF:materials` / `REF:fuels` /
`REF:warehouses` / `REF:production_lines` / `REF:infrastructures` / `REF:tech_nodes`。

**ctx 方法一览（规范名）**：

| 分类 | 方法 | 说明 |
| --- | --- | --- |
| 参与方 | `ctx.party(role)` | 参与方公司名 |
| | `ctx.company_field(role, key, default=0)` | 公司字段值（按财年取：精确 → 最新 → 无财年 → 默认） |
| | `ctx.company_industry(role)` | 公司产业 key |
| 输入项 | `ctx.input(key, default=None)` | 原值 |
| | `ctx.input_list(key)` | 清单行 `[{...}]` |
| | `ctx.input_number / input_text / input_bool(key, default)` | 归一化后的值 |
| | `ctx.number(value, default=0.0)` | 静态方法：宽松数字转换 |
| 基础数据 | `ctx.item(table, name, default=None)` | 条目**全部字段**（价格/容量/配比/坐标…） |
| | `ctx.items(table)` | 整表 `{名称: 字段字典}`（按表缓存） |
| | `ctx.item_names(table)` | 全部条目名（排序） |
| 原料价格 | `ctx.price(material, region='', default=None)` | 原料区域价；不给区域 = 全国均价 |
| | `ctx.prices(material)` | `{区域: 价格}` |
| | `ctx.price_names()` | 有参考价的原料名 |
| 地图节点 | `ctx.node_region(node, default='')` | 节点（名称或 ID）→ 区域名 |
| | `ctx.node_city(node, default='')` | 节点（名称或 ID）→ 城市名 |
| | `ctx.node_regions()` / `ctx.node_cities()` | `{节点名: 区域/城市}` 只读副本 |

**统一约定**：

1. 查不到一律返回 `None` 或传入的 `default`，**不抛异常**；
2. `ctx.item` / `ctx.items` 支持 12 张表：`materials` / `parts` / `products` / `map_nodes` /
   `cities` / `vehicles` / `companies` / `fuels` / `tech_nodes` / `infrastructures` /
   `warehouses` / `production_lines`；
3. `ctx.price` 的返回值单位与原料「按地点价格」一致；零件/产品/地点没有价格表；
4. 方法都是**只读**：要改数据必须返回 `Effect`。

```python
rows = ctx.input_list('零件清单')          # [{'item': '齿轮', 'quantity': '2'}, ...]

info = ctx.item('warehouses', '原料仓')        # {'capacity': 100.0, 'price': 80.0, 'type': 'MATERIAL'}
info = ctx.item('production_lines', '装配线')   # {'price': 300.0, 'labor_count': 5.0, 'max_per_year': 1000.0}
info = ctx.item('fuels', '柴油')              # {'price_per_liter': 6.5}
unit = ctx.price('铁', '长平省')              # 原料按区域价（原料没有单一价格）
names = ctx.item_names('fuels')              # ['柴油', ...]（排序后的全部条目名）
region = ctx.node_region('松平')             # 节点名或 ID 都行
```

**弃用别名**（仍可用，内部转调规范名；新插件请用左列规范名）：

| 旧名 | 规范名 |
| --- | --- |
| `ctx.item_detail(表, 名)` | `ctx.item(表, 名)` |
| `ctx.item_details(表)` | `ctx.items(表)` |
| `ctx.material_price(原料, 区域)` | `ctx.price(原料, 区域)` |
| `ctx.material_price_map(原料)` | `ctx.prices(原料)` |
| `ctx.price_names()` | `ctx.price_names()` |
| `ctx.region_of` / `ctx.region_of_node` | `ctx.node_region(节点)` |
| `ctx.city_of` / `ctx.city_of_node` | `ctx.node_city(节点)` |
| `ctx.node_regions()` | `ctx.node_regions()` |
| `ctx.node_city_map()` | `ctx.node_cities()` |
| `ctx.basedata(表, 编码)` | 引擎未注入数据，恒 `None`；改用 `ctx.item` |

`ctx.item` 返回条目**全部字段**（除 `id` / 创建时间 / 更新时间；名称本身是字典的键），
字段名与基础数据模型一致；`Decimal` 转 float，外键取关联对象名称（如地图节点 `node_type`
返回「城市点位」）。关系型数据额外展开：

| 表 | 额外补充字段 |
| --- | --- |
| `materials` | `origin` 产地（名称列表）、`node_prices` 按地点价格 `{节点ID: 价格}` |
| `parts` | `materials`：原料配比 `{原料: 比例}` |
| `products` | `parts`：零件配比 `{零件: 比例}` |
| `tech_nodes` | `prerequisites` 前置科技名称列表 |

例：仓库 `{capacity, price, type}`；基建 `{footprint, price, activation_price, employment_rate_bonus,
population_bonus, high_quality_population_bonus, happiness_index_bonus, per_capita_income_bonus,
carbon_reduction_bonus}`；生产线 `{price, labor_count, max_per_year}`；地图节点
`{region, city, x, y, node_type}`；载具 `{price, fuel, fuel_consumption_per_km, ...}`；
城市 `{region, city, x, y}`；公司 `{industry}`。

旧系统口径小结（`dist/old_backup_package` 老合同）：办公室只扣 `yinhangzhanghu`；选址地扣钱 +
`location SET 选址地`；买地扣钱（面积 × 160）+ `quyumianji ADD 面积`；劳动力扣钱 + 按产业加开采/加工上限。
需要「钱从买方到卖方」时用两个 `Effect`（`SUB`/`ADD`），只向系统购买时只 `SUB` 买方。

**输入项取值**：`ctx.input(key)` 返回合同里存的原值（可能是 `str`/`int`/`float`/`bool`，取决于录入方式——
比赛包导入的数字常常是字符串）。需要确定类型时用 `ctx.input_number(key, 默认值)`、
`ctx.input_text(key, 默认值)`、`ctx.input_bool(key, 默认值)`，它们会安全归一化。

| `check(ctx) -> list[str]` | 前置检查，返回问题列表（空 = 通过） |
| `apply(ctx) -> list[Effect]` | 字段修改，返回效果列表 |

**类别前缀**（历史字段，D13）：插件可声明 `NUMBER_PREFIX = "PO"`；**当前统一编号不再使用该前缀**，格式为 `比赛代码-FY财年-5位自增流水`（如 `49-FY0-00001`）。

#### 3.2 效果（Effect）规范

`apply(ctx)` 返回 ``list[Effect]``，落账顺序即列表顺序。效果构造：

```python
Effect(company, field, op, value, region='')     # 完整写法
Effect.add(company, field, value, region='')     # 等价于 op='ADD'
Effect.sub(company, field, value, region='')     # 等价于 op='SUB'
Effect.set(company, field, value, region='')     # 等价于 op='SET'
Effect.ADD / Effect.SUB / Effect.SET             # 常量，可直接给 op 用
```

| 参数 | 约定 |
| --- | --- |
| `company` | 参与方角色（`'买方'`）或公司名；都匹配不到时执行阶段报「效果指向未知公司/角色」 |
| `field` | 公司字段键（产业插件的 `FIELDS[].key`）；区域效果时是区域字段键 |
| `op` | `ADD` 加 / `SUB` 减（非数值按 0 计）；`SET` 覆盖（回滚 = 恢复落账前快照） |
| `value` | 数值（ADD/SUB）或字段值（SET，可写字典/文本） |
| `region` | 非空 = **区域字段**效果；落账前校验公司「所在区域」= 该区域名并满足字段条件 |

约定：

1. 只返回 `Effect`，**不直接改数据**；`ctx` 的方法全都是只读的；
2. 同一合同内可以对同一字段返回多个效果，按列表顺序依次作用；
3. 不需要改任何字段的记录型合同，`apply` 返回 `[]`；
4. 非法 `op`（如 `MUL`）在 `Effect(...)` 构造时就抛 `ValueError`，插件加载/执行会转成业务错误。

**城市节点 → 区域名**：插件可以拿 `ctx.node_region(节点名)` 把导入的城市数据换成区域名，
直接喂给 `Effect(region=...)`；节点也可以传 ID（`ctx.node_region(12)`），
`ctx.node_regions()` 返回 {节点名: 区域名} 的只读副本。

```python
def apply(ctx):
    region = ctx.node_region(ctx.input('city'))   # 例如 "上海" → "华东"
    if not region:
        return []
    return [Effect(company="buyer", field="market_capacity", op="ADD",
                   value=10, region=region)]
```

节点没有归属区域时 `region_of` 返回空串（第二个参数可给默认值），合同落账前仍会按
「公司所在区域 = 该区域名」与字段附加条件做校验。

**节点归属城市**：导入时会把车站/机场/码头按「城市名 + 方位/设施后缀」解析到所属城市
（如 `松平南`→松平、`樟港国际机场`→樟港），矿点与无名节点按坐标取就近城市；
结果写在 `MapNode.city`，可用 `python manage.py assign_map_cities [--competition 49]` 重跑。

**原料参考价（按原料名 + 城市/区域查价）**：引擎把原料表「按地点价格」
（`Material.node_prices`，`{地图节点ID: 价格}`）按节点所属区域折算后注入 ctx：

| 用法 | 说明 |
| --- | --- |
| `ctx.price(原料名, 地区)` | 该地区参考价；查不到返回 `None`（可给 `default`） |
| `ctx.price(原料名)` | 不给地区时返回各地区价格均值（全国参考价） |
| `ctx.prices(原料名)` | `{地区: 价格}` 只读副本 |
| `ctx.price_names()` | 有参考价的原料名列表 |

同一区域有多个城市时取均值；价格 `<= 0`（建库时预置的空价）视为未填，不参与平均。
原料采购合同插件对外提供 `query_price(ctx, 原料名, 地区='')`、`query_price_map(ctx, 原料名)`
与 `fill_unit_price(ctx, 行列表, 地区='')`（只补单价为 0 的行），可直接拿到查价能力：

```python
def check(ctx):
    price = query_price(ctx, '铁', ctx.node_region(ctx.input('city')))
    ...
```

## 4. 产业类型插件 `industry_<key>.py`

### 4.1 公式字段与循环依赖（导入即拒绝计算）

产业插件的 `FIELDS[].formula` 会落成「公式计算字段」（`is_calculated=True`）。**导入时**系统会：

1. 解析每个公式引用的字段键（排除 `round/log/IF` 等函数名）；
2. 用强连通分量找出循环依赖（含自引用 `a = a + 1`）；
3. 把环内字段标记为 `meta.formulaCycle = true`，**拒绝计算**（不写派生值、不参与重算）；
4. 在导入报告的 `warnings` 里逐环提示：

```
循环产业：公式循环 a → b → a，已拒绝计算（这些字段不会参与重算，请修正公式后重新导入）
```

- 非循环字段照常计算；依赖环字段的公式会用环字段的现有值（通常为空 = 0）；
- 修正公式后**重新导入**会重新判定，标记自动清除、字段恢复计算；
- 比赛 51 现有 10 个公式字段检测为无环（0 个标记）。

支持的公式语法：数字 / 字段键 / `+ - * / % **` / 比较（`< <= > >= == !=`）/
`and or not` / 函数 `IF`、`round`、`roundTo`、`min`、`max`、`abs`、`sqrt`、`pow`、
`log(x[, base])`、`ln`、`floor`、`ceil`、`int`。未知函数与属性访问一律报错（导入时字段保留但不计算）。

见重构方案 §8.2，必备元素：`INDUSTRY_KEY`、`INDUSTRY_NAME`、`FIELDS`（字段、公式、数据类型、初始值、数据表归属）、可选 `initial_values()`、`recompute(fields)`。

字段定义项：`key, name, type(NUMBER/TEXT/BOOL/REF/DATE), default, formula?, table(entity|finance), timerEnabled?, timerTrigger(FY_START|FY_END)`。

### 7.1 重导入幂等（2026-10 决策）

**比赛开始报名后仍允许重新导入比赛包**（无状态限制），因此合同实例导入必须幂等：

- 每条合同按**指纹**识别——`sha256(合同类型 + 名称 + 参与方(角色↔公司) + 输入项)`，落在
  `contracts.import_fingerprint`（本改动之前导入/手工建的合同由迁移一次性补算）；
- 重导入时若同指纹合同已存在 → **跳过**，不重复建（同一份包内重复行同样跳过）；
- 包内改动了名称/参与方/输入 → 指纹变化 → 视为**新合同**（旧合同保留，不会被覆盖）；
- 已被软删除的同指纹合同**不会**因重导入而复活；
- 其余内容的重导入影响：产业字段 `update_or_create`（新增/更新，包内删掉的字段不删）；
  **比赛库不清空、公司/公司字段值/队伍/10 类基础数据不受影响**；`dashboard.json` 存在则覆盖布局。

## 8. 导入编排与失败策略（§9.2）

```
上传 → 解压 + manifest/SHA-256 校验 → AST 静态扫描插件
     → CREATE DATABASE comp_<id> + migrate → 产业插件 → 字段迁移/初始值
     → 合同插件注册（暴露接口）→ 合同实例导入 → 导入报告
     （基础数据不随包导入，改由系统「数据管理」页维护；包内旧数据表忽略并提示）
```

- **失败策略**：任一阶段出现错误 → 中止并**整体回滚**（删除本次创建的比赛库/注册的插件版本）；报告列出每个文件的错误与警告；
- 插件执行调用审计、导入报告持久化到全局库 `packages.importReport`。

### 导入报告结构（`importReport` JSON）

```json
{
  "status": "SUCCESS | FAILED",
  "startedAt": "...", "finishedAt": "...",
  "files": [{"file": "sheets/industries.xlsx", "stage": "industries", "rows": 0, "errors": [], "warnings": []}],
  "plugins": [{"file": "...", "key": "purchase", "kind": "CONTRACT", "version": "1.0.0", "sha256": "..."}],
  "createdDatabase": "comp_12",
  "fieldMigrations": [{"industryKey": "manufacturer", "added": 12, "backfilled": 36}],
  "contractsCreated": 2, "contractsSkipped": 0,
  "errors": [], "warnings": []
}
```

`contractsSkipped` 为重导入去重跳过的合同数（§7.1），跳过的行在 `warnings` 里逐条列出。

## 11. 仪表盘样式文件 `dashboard.json`（v1.1 增补，可选）

包根放置 `dashboard.json`（或 manifest 用 `dashboard: <文件名>` 指定）。**可选**：缺失则该比赛无仪表盘布局（页面显示空态）；格式非法只进导入报告 `warnings` 并保留旧布局，不阻断导入。

> 示例包生成器（`scripts/make_sample_package.py`）与包工程工具 `init` 现在都会生成示例
> `dashboard.json`；`tools/package-tools` 的 `check` 也会校验其结构。

```json
{
  "title": "经营看板",
  "components": [
    {"id": "revenue", "type": "number", "title": "总营收", "zone": "top",
     "bind": {"table": "finance", "fieldKey": "revenue", "aggregate": "sum"},
     "suffix": "万元", "description": "所有可操作公司求和"},
    {"id": "cash", "type": "table", "title": "各公司现金", "zone": "bottom",
     "bind": {"table": "finance", "fieldKey": "cash", "aggregate": "latest"}},
    {"id": "note", "type": "text", "title": "规则说明", "zone": "bottom", "text": "……"}
  ],
  "industries": {
    "steel": {
      "title": "钢铁产业看板",
      "components": [
        {"id": "cap", "type": "number", "title": "产能", "zone": "top",
         "bind": {"table": "entity", "fieldKey": "steelCapacity", "aggregate": "sum"}},
        {"id": "rate", "type": "gauge", "title": "产能利用率", "zone": "top",
         "bind": {"table": "entity", "fieldKey": "capacityRate", "aggregate": "latest", "max": 100}}
      ]
    },
    "auto": {
      "title": "汽车产业看板",
      "components": [
        {"id": "sales", "type": "number", "title": "销量",
         "bind": {"table": "finance", "fieldKey": "salesVolume", "aggregate": "sum"}}
      ]
    }
  }
}
```

字段规则：
- `type` ∈ `number | gauge | table | text`；`zone` ∈ `top | bottom`（缺省 `top`）；
- `bind.table` ∈ `entity | finance`（实体信息表 / 财务报表），`bind.fieldKey` = 产业字段键；
- `bind.aggregate` ∈ `sum | latest | average`（缺省 `latest`）；
- `gauge` 可带 `bind.max`（缺省 100，用于百分比）；`text` 只需 `text`；
- 导入报告新增 `dashboard: {status: OK|INVALID|SKIPPED, file, components, industries}`。

**按产业分屏（v2，2026-10 决策）**：
- `components` = **通用区**：「全部」页签渲染，聚合**全部**可操作公司；
- `industries.<产业key>` = 该产业**专属页签**（`{title?, components}`）：只聚合**该产业**的公司，
  `bind.fieldKey` 即该产业插件 `FIELDS` 里的字段键（不同产业字段天然不同 → "按产业区分界面与绑定字段"）；
- 前端页签 = 「全部」+ 我有公司的产业 + 布局里定义的产业；产业页签优先用专属布局，
  缺失时退化为通用布局但**聚合范围收敛到该产业公司**；表格列含公司/产业/数值。

渲染口径：公司集合 = 当前用户可操作公司（本队公司或被分配管理的公司，`GET /companies` 天然按此过滤）；
字段取值 = 该字段 `values` 字典最后一个值（与区域总览同口径）。API：`GET /api/competitions/{cid}/dashboard`。

## 12. 区域字段定义 `region-fields.json`（v1.2 增补，可选）

包根放置 `region-fields.json`（或 manifest 用 `regionFields: <文件名>` 指定）。定义是**比赛级**（所有区域共用一套字段），字段值按区域存；区域总览「区域数据」直接展示每个区域的字段值。

```json
{
  "fields": [
    {"key": "market_capacity", "name": "市场容量", "type": "NUMBER", "default": 100,
     "condition": {"fieldKey": "license", "op": "eq", "value": true}}
  ]
}
```

- `type` ∈ `NUMBER | TEXT | BOOL | DATE`（实体字段，不按财年）；
- `condition`（可选）：合同修改该字段时的**附加**条件；`source` 缺省 `COMPANY`（公司实体字段），
  设为 `REGION` 时引用目标区域的其他区域字段（如 `{"source":"REGION","fieldKey":"level","op":"eq","value":"一线"}`）；
  默认规则是公司「所在区域」字段**包含**该区域名（支持 `"华东,华南"`、`"华东、华南"`、`["华东","华南"]` 多值）时才允许通过合同修改；
- 重导入以包为准：同名字段更新定义，包中移除的字段连同各区域值一起删除；
- 导入报告新增 `regionFields: {status: OK|INVALID|SKIPPED, file, count}`；格式非法阻断导入。
