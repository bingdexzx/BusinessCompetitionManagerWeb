# 《比赛包格式规范》v1.1

> 依据：重构方案 §9（比赛包格式与导入机制）、§8（Python 插件规范）、决策 D15
> 状态：**v1.1**——v1.0 五项取舍经需求方确认（2026-10-10）；v1.1 导入方式变更（2026-10-12）：
> **比赛包只含产业信息与合同信息，不含基础数据**——燃料/仓库/载具等 10 类改由系统
> 「数据管理」页维护（旧版包内数据表格导入时忽略并提示）。
> 配套：示例包由 `scripts/make_sample_package.py` 生成（2 个合同插件、1 个产业插件 + industries/contracts 表格）。

---

## 1. 总体结构

一次导入即搭建整场比赛**产业与合同**底座的标准压缩包（`.zip`）：

```
competition_package.zip
  manifest.yaml              # 包元数据、插件清单与哈希（必须）
  plugins/
    contract_purchase.py     # 合同类型插件（一个文件一类合同）
    contract_loan.py
    industry_manufacturer.py # 产业类型插件（一个文件一个产业）
  sheets/
    industries.xlsx          # 产业信息、产业字段（对账）
    contracts.xlsx           # 合同信息（合同实例）
```

- **表格 = 数据，Python = 逻辑**：业务规则（检查/修改/公式）全部在插件里；表格只承载产业信息与合同实例。
- **基础数据不随包**：燃料/仓库/载具/地图/原料/产品/零件/基建/科技树/生产线在系统「数据管理」页维护。
- 编码：xlsx（推荐）或 csv（同名 `*.csv` 可替代 `*.xlsx`）；所有文本 UTF-8。
- 包大小上限默认 100 MB；单表格行数上限默认 50,000。

## 2. manifest.yaml

```yaml
packageVersion: "1.0"            # 包格式版本
competition:                     # 建议的比赛信息（可被导入后编辑）
  name: "2025 商业对抗赛"
  coverImage: "https://.../cover.png"
  hostSchool: "示例大学"          # 按名称匹配学校，不存在则报告警告
  location: "北京"
  staffingInfo: "主席团 5 人"
plugins:
  - file: plugins/contract_purchase.py
    kind: CONTRACT               # CONTRACT | INDUSTRY
    key: purchase                # 与插件内 *_KEY 一致
    name: "采购合同"
    version: "1.0.0"             # 语义化版本；key+version+sha256 唯一
    sha256: "<文件 SHA-256>"
  - file: plugins/industry_manufacturer.py
    kind: INDUSTRY
    key: manufacturer
    name: "制造业"
    version: "1.0.0"
    sha256: "<文件 SHA-256>"
sheets:
  - file: sheets/industries.xlsx
    sha256: "<文件 SHA-256>"     # 可选；提供则校验
  - file: sheets/contracts.xlsx
    sha256: "<文件 SHA-256>"
```

校验规则：
1. `packageVersion` 主版本必须为 `1`；
2. manifest 声明的插件/表格必须真实存在，多出的文件报**警告**；
3. 声明 `sha256` 的文件逐一核对，不一致为**错误**（整包拒收）；
4. `kind` 与文件名前缀必须一致（`contract_` / `industry_`）；`key` 与插件内 `CONTRACT_KEY` / `INDUSTRY_KEY` 必须一致。

## 3. 合同类型插件 `contract_<key>.py`

见重构方案 §8.1，必备元素：

| 元素 | 说明 |
|------|------|
| `CONTRACT_KEY` | 唯一标识（与 manifest 一致） |
| `CONTRACT_NAME` | 展示名 |
| `PARTY_ROLES` | 参与方列表 `[{role, label, optional?}]`，可扩展任意方数 |
| `INPUT_SCHEMA` | 输入定义 `[{key, label, type, min?, max?, ref?}]`，type ∈ `NUMBER/TEXT/BOOL/REF:<表格>` |
| `check(ctx) -> list[str]` | 前置检查，返回问题列表（空 = 通过） |
| `apply(ctx) -> list[Effect]` | 字段修改，返回效果列表 |

**类别前缀**（统一编号用，D13）：插件内可选声明 `NUMBER_PREFIX = "PO"`；缺省取 `CONTRACT_KEY` 前两个字符大写。

## 4. 产业类型插件 `industry_<key>.py`

见重构方案 §8.2，必备元素：`INDUSTRY_KEY`、`INDUSTRY_NAME`、`FIELDS`（字段、公式、数据类型、初始值、数据表归属）、可选 `initial_values()`、`recompute(fields)`。

字段定义项：`key, name, type(NUMBER/TEXT/BOOL/REF/DATE), default, formula?, table(entity|finance), timerEnabled?, timerTrigger(FY_START|FY_END)`。

## 5. 基础数据（**不随比赛包提供**；列定义作数据字典参考）

> 导入方式变更（v1.1）：燃料/仓库/载具等 10 类基础数据改由系统**「数据管理」页**维护；
> 比赛包内如出现下列表格文件，导入时**忽略并提示**。以下列定义保留作数据字典。

通用规则：
- 第 1 行为表头；列名大小写不敏感；
- **标准列**必须存在（缺失 → 错误）；**扩展列**（表头未在下表列出）原样存入 `meta` JSON 并报告**警告**；
- `code` 在本表内唯一（重复 → 错误）；`REF:*` 引用列填目标表的 `code`（悬空引用 → 错误）；
- 空单元格视为 NULL；`notes` 任意文本。

| 表 | 标准列（* 必填） | 说明 |
|----|------------------|------|
| `fuels.xlsx` 燃料 | `code*`, `name*`, `unit`, `energyValue`, `price` | 单位/热值/单价 |
| `warehouses.xlsx` 仓库 | `code*`, `name*`, `capacity`, `regionCode(REF:maps)` | 容量、所在地区 |
| `vehicles.xlsx` 载具 | `code*`, `name*`, `vehicleType`, `loadCapacity`, `speed`, `fuelCode(REF:fuels)`, `fuelConsumption` | 载重/速度/油耗 |
| `maps.xlsx` 地图 | `code*`, `name*`, `regionType`, `adjacentCodes`, `distance` | `adjacentCodes` 逗号分隔地区 code |
| `materials.xlsx` 原料 | `code*`, `name*`, `unit`, `basePrice` | |
| `products.xlsx` 产品 | `code*`, `name*`, `unit`, `basePrice` | |
| `parts.xlsx` 零件 | `code*`, `name*`, `unit`, `basePrice`, `compatibleTypes` | 逗号分隔适配载具类型 |
| `infrastructures.xlsx` 基建 | `code*`, `name*`, `infraType`, `buildCost`, `maintenanceCost`, `effect` | `effect` 为 JSON 文本 |
| `tech_tree.xlsx` 科技树 | `code*`, `name*`, `tier`, `prerequisiteCodes`, `researchCost`, `effect` | 前置科技逗号分隔 |
| `production_lines.xlsx` 生产线 | `code*`, `name*`, `inputs`, `outputs`, `capacity`, `buildCost` | `inputs`/`outputs` 为 JSON 文本：`{"<物料code>": 数量}` |

## 6. industries.xlsx（产业信息、产业字段）

双工作表：

**工作表 `industries`（产业信息）**

| 列 | 说明 |
|----|------|
| `industryKey*` | 与产业插件 `INDUSTRY_KEY` 一致 |
| `name*` | 产业名 |
| `pluginFile*` | `plugins/industry_*.py` |
| `description` | 描述 |

**工作表 `fields`（产业字段，可选，对账用）**

| 列 | 说明 |
|----|------|
| `industryKey*`, `fieldKey*`, `name`, `type`, `defaultValue`, `formula`, `table`, `isCalculated`, `timerEnabled`, `timerTrigger` | 与插件 `FIELDS` 逐项对账；**不一致报错误**（防止表格与插件两套真相） |

> 待确认 #1：产业字段的**权威来源**约定为插件 `FIELDS`（表格仅对账）；如需求方要求表格可覆盖字段定义，请在确认时说明。

## 7. contracts.xlsx（合同信息 = 合同实例）

| 列 | 说明 |
|----|------|
| `contractTypeKey*` | 对应合同插件 `CONTRACT_KEY` |
| `name` | 合同名 |
| `partiesJSON*` | `[{"role": "buyer", "companyName": "A公司"}, ...]`，role 必须符合插件 `PARTY_ROLES` |
| `inputsJSON*` | `{"product": "P1", "quantity": 10, ...}`，符合插件 `INPUT_SCHEMA` |
| `fiscalYear` | 财年序号（可空；财年由后续开赛流程创建） |
| `notes` | 备注 |

导入语义（待确认 #2）：
- 合同实例创建为 **`DRAFT` 草稿态**，进入正常状态机（M3 起逐方确认/编号/执行）；
- 引用的公司按 `companyName` **自动建档**到比赛库 `companies`（包内暂无公司清单表）。

## 8. 导入编排与失败策略（§9.2）

```
上传 → 解压 + manifest/SHA-256 校验 → AST 静态扫描插件
     → CREATE DATABASE comp_<id> + migrate → 产业插件 → 字段迁移/初始值
     → 合同插件注册（暴露接口）→ 合同实例导入 → 导入报告
     （基础数据不随包导入，改由系统「数据管理」页维护；包内旧数据表忽略并提示）
```

- **失败策略**：任一阶段出现错误 → 中止并**整体回滚**（删除本次创建的比赛库/注册的插件版本）；报告列出每个文件的错误与警告；
- 插件执行调用审计、导入报告持久化到全局库 `packages.importReport`。

### 导入报告结构（`importReport` JSON）

```json
{
  "status": "SUCCESS | FAILED",
  "startedAt": "...", "finishedAt": "...",
  "files": [{"file": "sheets/industries.xlsx", "stage": "industries", "rows": 0, "errors": [], "warnings": []}],
  "plugins": [{"file": "...", "key": "purchase", "kind": "CONTRACT", "version": "1.0.0", "sha256": "..."}],
  "createdDatabase": "comp_12",
  "fieldMigrations": [{"industryKey": "manufacturer", "added": 12, "backfilled": 36}],
  "errors": [], "warnings": []
}
```

## 9. 权限与审计（§5.4）

- 上传/导入仅**系统超管**与**本比赛超管**（M1 阶段：系统超管）；
- 每次上传记录（人、时间、文件 SHA-256）入全局库 `packages`，并自动写网络日志；
- 插件 AST 黑名单：`os.system/subprocess/socket/eval/exec/__import__/open/ctypes` 等（可配置）；发现即拒收。
