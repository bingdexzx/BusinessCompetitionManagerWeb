# 独立压测工具（单文件 .bat）

**只需要 Windows 的 cmd + Python 3.10+**，不依赖 Django、不装任何第三方包，
放在任意目录、从任意位置运行都可以（报告写在 bat 旁边的 `reports\loadtest`）。

## 快速开始

1. 双击 **`loadtest.bat`**（或在 cmd 里直接运行 `loadtest.bat`）；
2. 按提示输入：目标网址 → 超管账号 → 密码（输入不回显）→ 压测模式 → 并发数 →
   持续秒数或请求总数 → 思考时间；
3. 探测接口与压测过程中会显示实时进度条；
4. 跑完在 `loadtest.bat` 同目录的 `reports\loadtest\` 下生成 Markdown + HTML 报告。

也可以直接带参数（适合脚本/CI，写在 cmd 里）：

```bat
# 模式一：固定时长
loadtest.bat --base-url http://127.0.0.1:8000 ^
  --username full_admin --password "***" ^
  --users 20 --duration 60 --think 1 --timeout 30 --yes

# 模式二：固定请求总数（发完 20000 个请求，看总耗时）
loadtest.bat --base-url http://127.0.0.1:8000 ^
  --username full_admin --password "***" ^
  --mode requests --users 50 --requests 20000 --think 0 --timeout 30 --yes
```

> 只要系统有 `py` 启动器或 `python` 在 PATH 里即可；脚本会优先用 `py -3`，
> 避免命中 Microsoft Store 的 python 占位符。

## 参数

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `--base-url` | 目标网址（http/https） | 交互询问 |
| `--username` | 超级管理员账号 | 交互询问 |
| `--password` | 密码（建议交互输入，避免进历史） | 交互询问 |
| `--mode` | `duration`（按时长）/ `requests`（按请求总数） | 交互询问，默认 duration |
| `--users` | 并发虚拟用户数 | 交互询问，默认 10 |
| `--duration` | 持续压测秒数（duration 模式） | 交互询问，默认 30 |
| `--requests` | 固定请求总数（requests 模式） | 交互询问，默认 `max(100, 并发×10)` |
| `--think` | 每轮请求后的思考时间（秒） | 交互询问，默认 1.0 |
| `--timeout` | 单请求超时秒数 | 60 |
| `--cid` | 指定比赛 ID | 自动挑第一个可用比赛 |
| `--report-dir` | 报告目录（bat 默认传脚本旁 `reports\loadtest`） | 脚本旁 |
| `--insecure` | HTTPS 忽略证书校验 | 关闭 |
| `--no-html` | 只生成 Markdown | 关闭 |
| `--yes` | 跳过开始前确认 | 关闭 |
| `--fail-on-error` | 有错误时退出码非 0（CI 门禁） | 关闭 |

## 两种模式与「巅峰性能」怎么测

| 模式 | 指标 | 适合 |
| --- | --- | --- |
| `duration` 固定时长 | 稳态 QPS、P50/P95/P99 | 模拟持续在线压力、观察长尾与稳定性 |
| `requests` 固定请求数 | **完成 N 个请求的总耗时**、折算 QPS、分接口延迟 | 对比不同并发下的「处理能力上限」、版本前后性能回归 |

`requests` 模式的正确打开方式：

1. **思考时间设为 0**（`--think 0`），否则测到的是业务节奏，不是吞吐；
2. 请求数要足够大，避免启动/探测阶段占比过高；建议至少 `并发 × 接口数 × 3`，
   例如 50 并发 × 80 接口，先跑 20000 个请求；
3. 固定同一请求数，横向扫并发：`--users 10/20/50/100`，看「总耗时」何时不再下降、
   P95 何时开始抬升，那个拐点就是当前环境的吞吐上限；
4. 固定并发，纵向对比版本：同一 `--users`、`--requests`，升级前后各跑一次。

注意：

- `requests` 是**闭环**模式，并发数包含客户端等待时间；它回答的是「这些并发能多快干完 N 个活」，
  不是严格的「每秒固定打 N 个请求」；
- 如果要做 SLO/限流验证（固定 RPS、看超时），用 `duration` 模式先跑稳态；
- 短请求数会受 TCP 建连、JIT/缓存预热影响，结论优先看多次运行的中位数。

## 进度与反馈

- 登录后先显示 `探测 [####----] 42%  3/8 合同列表`；
- 压测开始后显示实时进度：`压测 [######----] 60%  18/30s  请求 952  错误 0  QPS 52.1`；
- 非 TTY 环境（CI、重定向到文件）自动关闭进度条，避免日志刷屏；
- 指定 `--yes` 时使用默认并发/时长，不交互询问。

## 压测哪些接口

登录后按以下范围**自动探测**，只保留返回 200 的只读接口（全部 GET，不写数据）：

- **全局**：健康检查、比赛列表、当前用户、版本、更新日志、我的获奖/票据/奖牌/设备、
  收件箱/发件箱/通讯录、学校、用户、插件注册表、网络日志、设备、限流配置/记录、奖牌管理；
- **比赛**：比赛详情/meta/权限/仪表盘、公司、队伍、成员、邀请、作业、合同类型/列表/增量、
  产业与产业字段、比赛包、财年、区域/地图概览/区域字段、消费者需求、股票行情/同步/市场/盘口/
  委托/账户、字段日志、审计流水、结算配置/候选/结果、获奖名单/发放、定时器、比赛消息；
- **数据管理**：fuels、warehouses、vehicles、maps、materials、products、parts、
  infrastructures、tech_tree、production_lines；
- **详情样本**：先取列表第一条，再探测公司实体表/财务报表/产业字段/区域、合同详情/效果/台账、
  区域详情/总览卡片、财年备份、股票详情/K 线、队伍详情。

> 取不到样本或接口返回 403/404 时自动跳过；可用接口数量、跳过原因会在控制台输出。
> 目前完整环境可覆盖约 80 个只读接口。

reports\loadtest\loadtest_20261125_160100.md    # 文本（可贴群/入库）
reports\loadtest\loadtest_20261125_160100.html  # 浏览器直接打开

内容：目标/账号/比赛/并发/思考时间 → 总体指标（QPS、错误率、P50/P95/P99）
→ 分接口表（含状态码分布）→ 自动结论与建议。

## 实现说明（维护用）

- `loadtest.bat` 是**单文件版**：前半段是批处理（找 Python → 用 PowerShell 把内嵌源码抽到
  `%TEMP%` 执行 → 删除临时文件），后半段是完整的 Python 源码；
- 源码在 `loadtest.py`；修改后运行 `python build_bat.py` 重新生成 `.bat`；
- 报告目录不可写时（如 bat 放在只读位置），会自动退回 `%USERPROFILE%\bcm_loadtest_reports`。

## 注意

- 只读压测（全 GET），不会创建/修改/删除数据；
- 默认 10 并发 × 30s，建议先小规模试跑再逐步加压；
- 压测时后端请用 `run_servers.py --no-reload`（开发热重载会中途重启 worker，长尾数据不准）；
- 超管密码不要写进脚本/仓库，建议交互输入。
